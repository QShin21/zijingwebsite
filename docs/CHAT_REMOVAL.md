# 移除社群聊天 · 2026-10-11

用户要求同时从微信小程序和网页版删除社群聊天。本次保留活动与通知、论坛、评论、点赞与参加意愿、社群风采、管理员联系方式、账号及审核流程。

## 改动

- 网页版删除聊天页面与组件、消息发送和隐藏动作、feed、SSE、聊天图片读取、表情搜索与图片处理库，以及专用样式。
- Payload 不再注册 `community-messages`，CMS 和 GraphQL 不再提供聊天集合。旧聊天页面、消息接口、图片、表情和后台集合地址在 Proxy 中统一返回 404，响应禁止缓存，登录用户同样无法调用。
- 小程序删除聊天路由、页面、入口与 SSE 客户端；社群分区保留活动与通知、论坛、社群风采。原生页面由 14 个减为 13 个，5 个底部导航入口保留。
- 保留历史数据库表、记录、图片数据和既有迁移。此次不新增迁移，不执行数据删除；回退只需恢复配套应用代码和构建。

## 验证

网页版工作分支通过 87 项单元 / 数据库测试、类型检查、lint 和 Next.js 生产构建。7 项生产构建浏览器回归覆盖三个社群分区、访客及已登录用户访问旧聊天地址 / GET / POST / PATCH 均被拒绝、登录、论坛发帖和回复、活动互动、风采投稿审核及 390 / 1440px 布局。

小程序分支通过 102 项单元 / 数据库测试、类型检查、lint 和 Next.js 生产构建；原生检查为 13 个页面、63 个文件、117059 字节，合法域名校验保持开启。官方开发者工具已上传开发版本 `0.1.1`，编译包 123387 字节。两项明确使用模拟状态的原生 UI 检查确认访客限制和三个社群分区 / 无聊天入口，不作为真实账号验证。

2026-10-11 模拟器实际请求网站配置、活动和小程序能力接口均返回 200 JSON。前次域名拒绝已不再出现；实际手机扫码、邮件投递和真实账号操作仍需单独验证。

本地测试仅使用独立 PostgreSQL 库，浏览器使用临时测试账号和社群。测试服务器 origin 已与本机端口一致；SMTP 只指向 loopback，未发送真实邮件。原网站目录中 27 项未提交修改的文件摘要一致，未将这些修改纳入本次提交。

## 网页版上线与恢复

线上当前运行版本仍为 `42aa64d64b632f9e4ea206e070d34c04b02cf564`。部署候选使用 `littleapp` 分支的完整服务器源码，以保留已授权上线的小程序账号 / 验证 / 互动接口。`main` 只接收两端共用的聊天删除改动，后续小程序独立迭代继续在 `littleapp`。

上线前核对当前 104 份源码、依赖、环境和 Nginx 配置，保留旧构建、源码、配置文件和 `SOURCE_REVISION`；独立构建新版本，在临时 loopback 端口验证健康检查、旧聊天入口 404、公开活动和小程序能力接口。通过后替换构建与源码，复核网站就绪与 FreeKill HTTPS / WebSocket。无需数据库迁移，不修改 DNS、环境、媒体或 FreeKill 配置。

发生异常时恢复旧构建、完整旧源码和版本标记，重启网站并复核就绪。旧聊天表不受本次变更影响，不需要数据库回退。详细候选及本地恢复资料在工作树被忽略的 `.data/` 中。

当前服务器仅完成只读盘点，网页版尚未部署此改动。根据仓库 `AGENTS.md` 的“生产部署……仍需相应授权”，本次线上替换需要用户授权；此前授权范围为新增小程序接口的部署。
