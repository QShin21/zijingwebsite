# 代表队荣誉 · 独立模块与集成合同

工作分支：`codex/team-honors-20261012`；验收基线：`beac037eafe88b9b82e171e15cfddcca351b838b`。

本模块拥有荣誉投稿、审核、批准记录的实时档案与社群风采置顶。队伍、招新、成员关系和队员简介由其他任务维护；不使用 `users.teams`、社群进群记录或 `seasons.members` 昵称阵容作为成员资格。

## 成员权威依赖

核心唯一维护 `team-memberships` 与 `src/lib/team-memberships.ts`。荣誉需要以下服务签名等价能力，所有写入必须复用调用方 `PayloadRequest` 的事务：

- 列出当前账号的有效成员关系，返回权威 `membership.id/member/team/season` 及队伍所属 `game`、是否允许新写入。
- 从当前事务实时核验 `member + team` 的有效成员关系，拒绝 left/revoked、账号停用、队伍停用及所属社群未开放；客户端的 status/game 不能参与判定。
- 读取队伍的当前启停与公开状态供档案判断。入队关系撤销和荣誉写入的并发必须冲突或串行化。
- 社群管理员使用当前 `communityOffices` 的 active + reviewShowcase 范围；社长/副社长保持已有全局权限。不能自行审核本人，骨干无全局荣誉材料能力。

正式签名到达前用荣誉专属隔离适配器默认拒绝成员写入，并以显式注入的合成权威做测试。接口替换后还需核心联合验证，隔离测试通过不能宣称完整成员权限通过。

已只读核对核心合同 `567e359907418a2ebdb14833cfc5838901a09892` 的 `getActiveTeamMembership(payload, {teamID,userID,req})`。`src/lib/team-honor-core-adapter.ts` 接收该真实函数，每个引用均重新核验，并在同一事务以共享行锁锁住队伍、作者和 membership，退出/撤销/停用的行更新必须等待或使荣誉事务冲突。列出本人队伍只从核心集合读取本人 `member` 的不透明引用，再由核心函数决定资格，没有状态回退或第二名单。

最终集成需在 `src/lib/team-honor-service.ts` 做下述局部替换，核心集合及类型必须先注册：

```ts
import { getActiveTeamMembership } from "./team-memberships";
import { createCoreTeamHonorAuthority } from "./team-honor-core-adapter";
export const teamHonorService = createTeamHonorService(
  createCoreTeamHonorAuthority({ getActiveTeamMembership }),
);
```

当前分支仍使用明确关闭写入的 `pendingHonorAuthority`；切勿把模块合成测试描述为真实成员权限联调通过。核心 `teamStatus=archived` 或旧 `archived=true` 撤下档案；核心的 resting 是否允许荣誉补录，完全沿用其当前有效成员判定。旧 unestablished 队伍的既有公开荣誉仍以历史来源展示，不赋予新投稿资格。

## 状态和公开规则

草稿 → 待审核；待审可撤回；退回/拒绝附具体说明，作者修改后可重提。所有作者创建（包括同时任管理员的队员）均不自动批准。保存修改会撤下当前批准投影，回到草稿，重新提交和由他人批准后展示。隐藏记录保留作者、批准版本和历史，重新提交须重新审核。

赛事日期记录获奖事实，不推断历史入队日期。新投稿引用核验后的唯一 membership；离队阻止新的作者写入和未批准记录的批准，既有批准历史不因离队删除。

证据图片复用已验收静态图片去元数据上传；视频复用受控本站 MP4 和 SHA-256 字节版本。每次提交、批准及公开投影核对版本。可变外链不能作为新荣誉的审核证据，不抓取任意 URL。

每个队伍仅有一个实时荣誉档案，链接在对应社群风采详情下。仅批准、证据版本仍有效且队伍/社群开放的记录进入档案；待审、退回、拒绝、草稿、隐藏材料不公开。档案为空或队伍停用时不显示置顶。普通风采分页继续按原集合单独分页。

历史 `honors` 已核验并已发布的记录以兼容投影纳入同一档案，不复制、不改作者、不假设有不存在的证据快照。历史来源使用原档案明确标识；原集合的草稿/未核验记录不纳入。新增迁移只创建荣誉投稿结构，保留原荣誉与赛季归属。

## 文件所有权和集成点

荣誉专属 `team-honor-*` 模型/服务、`team-honor-records` 集合、荣誉网页与 API、组件、测试和唯一命名迁移归此分支。`src/collections/index.ts` 只加入集合导入与注册；`src/migrations/index.ts` 只加新迁移；生成类型只增荣誉集合。风采列表只挂接置顶组件，父任务统一代表队/荣誉导航与最终路由。共享文件须按局部补丁集成，不能整文件覆盖核心和简介变更。

## 迁移与回滚

禁止生产迁移、生产测试资料或真实通知。演练使用新的本地合成数据库及独立媒体目录。迁移采用 additive 新表；应用回滚保留新表、历史批准和审核证据。`down` 禁止丢数据自动删除；如需物理移除，另行备份、审查与明确授权。
