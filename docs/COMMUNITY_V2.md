# 账号与社群 V2

> 2026-10-11 更新：论坛、评论回复及点赞等互动功能已移除；网页保留风采投稿及审核，小程序风采仅供查看。下文旧版本记录保留原日期与验收范围。

## 当前社群分区 · 2026-10-11

每个游戏社群保留首页，分区为 `/updates`、`/forum` 和 `/showcase`。标题旁入口从当前有效管理员与已批准的本社群申请中取昵称、微信名片；移除社群管理归属或暂停账号后不再显示。原始申请中的姓名、电话、邮箱继续私有。

活动与通知每页 10 条，详情页支持留言、点赞；活动支持可取消的参加意愿，每用户每条每类型唯一。论坛每页 20 条，可按时间或热度排序，置顶优先；精华集合独立筛选，热度为点赞及可见回复之和，由事务触发器维护。


访客仅开放活动与通知栏目；首页进入活动，其他栏目需要有效登录，导航同步收起。登录、注册、找回密码与隐私说明可公开访问。联系方式及社群 REST/GraphQL 入口均执行登录检查，保留原有角色、草稿和跨社群管理权限。

风采支持文字、最多 6 张照片（PNG/JPEG/WebP、各 2 MB）及 HTTPS 视频链接。普通成员提交即 pending，本人可查审核状态；本社群管理员、社长及副社长可批准、退回或隐藏，管理员可直接发布。图片和稿件一同受读取权限保护，经校验转为 1600px WebP；不在公开媒体库生成待审附件。B站 BV/AV 完整视频链接支持点击加载官方预览及外跳，b23 短链保留外跳；播放器参考 [B站官方文档](https://player.bilibili.com/)。

数据库迁移依次增加互动表、论坛管理字段/热度触发器及风采表，不删除既有业务数据。部署前备份并演练；含投稿的结构回退需使用审查后的备份，不执行删除投稿的 down。服务器 Next Server Action 上限 14 MB，本站 Nginx 上限 16 MB。

社群聊天已从网页版和小程序移除，包含消息发送、实时推送、聊天图片与表情搜索。旧聊天地址及消息集合入口返回 404；保留历史数据表和迁移，不执行清库。2026-09-28 的聊天部署与验收记录只代表当时版本。

注册和找回密码仅要求至少 8 位，不要求特定字符组成。申请社群管理员须填写姓名、手机号、上传微信个人名片二维码（PNG/JPEG/WebP、2 MB 以内），以及游戏和申请说明；提交完成提示添加社长微信 `yz167015` 备案。

审核页 `/community/review` 展示姓名、手机号、昵称、邮箱、账号状态、提交时间、申请说明和二维码，可批准或退回。联系资料仅由本人和有审核权限的负责人读取，二维码通过认证路由按申请权限访问并禁止缓存。历史不完整申请需退回后重提；新迁移只增加可空资料列，保留旧记录。备份须覆盖数据库，其中包含私有申请图片。

## 上线顺序

1. 在隔离数据库恢复一份脱敏备份，执行 `pnpm migrate`，核查旧账号、活动、媒体和草稿。历史迁移把旧 `admin/publisher` 映射为副社长，把旧 `editor/leader` 映射为社群管理员；原有多个等级保留最高等级。2026-09-26 昵称迁移删除数字账户字段，保留用户 ID、邮箱、密码、角色和昵称大小写，回填小写匹配键并创建唯一索引。若已有昵称忽略大小写后重名、包含 @ / 控制字符、首尾空白或不满足 2–40 字符，迁移停止且事务回滚；先在旧版管理流程中与本人核对并修正，再重试。发布前备份数据库，回滚需要恢复备份并配套旧版应用，不能通过 down 自动还原已删除的数字账户。
2. 在服务器受限的环境文件中设置 `SMTP_HOST`、`SMTP_PORT`、`SMTP_FROM`、`SMTP_USER`、`SMTP_PASSWORD`，用实际邮箱测试送达。邮件未配置时验证码注册与密码找回关闭并显示错误。
3. 设置 `PRESIDENT_CLAIM_EMAIL` 为指定社长的邮箱，停用旧 `PRESIDENT_CLAIM_ACCOUNT` 配置。指定邮箱验证码通过时，注册为社长；如果该邮箱已有旧账号，则在验证后升级旧账号并更新昵称与密码。昵称仍需通过唯一性检查。使用全新密码；聊天中出现过的密码不可继续用。认领成功后清除认领邮箱环境变量并重启服务，核对账号等级。
4. 在测试环境完成注册、登录、找回密码、申请与审核、发帖、跨社群越权、通知草稿与审核发布，再部署正式环境。此仓库提交不替代对测试服务器或正式服务器的操作。

## 四级权限

| 等级 | 权限 |
| --- | --- |
| 社长 | 全站发布、审核、账号等级及社群归属调整、站点设置 |
| 副社长 | 全站内容发布、审核社群申请、站点设置；不能调整账号等级 |
| 社群管理员 | 所负责游戏内直接发社群活动和通知、管理发言；全站活动、通知、荣誉、动态和影像先提交草稿，等社长或副社长审核 |
| 普通成员 | 浏览、论坛发帖、活动与影像与通知下留言回复；可申请管理已有或新游戏社群 |

社群管理员进入 `/admin` 创建全站内容草稿，将「审核状态」改为「待审核」。审核者在后台检查后发布；未经提交的社区投稿无法发布。审核社群申请在 `/community/review`；批准新游戏时自动发布游戏页面并创建论坛入口。用户可通过 `/community/apply` 提交申请。

用户使用昵称或邮箱登录，昵称唯一性与登录匹配忽略大小写，公开显示保留输入的大小写（例如 `Shin`）。内部匹配键由服务端派生，不能由调用者覆盖；数据库唯一索引处理并发冲突。用户的邮箱不能通过普通账号编辑接口修改；密码通过注册邮箱的六位验证码重设。验证码以 HMAC 摘要保存，10 分钟有效，最多错误五次，邮件 60 秒内不得重复发送，并有限流。用户新建账号必须在验证码通过之后；Payload 的公开用户创建接口关闭。普通浏览不要求登录。

## 运营边界

- 新社群是游戏项目档案和论坛、发言、社群活动通知的集合；它不自动生成未经核实的队伍、荣誉或成员资料。
- 社群内容为纯文本，React 转义输出；禁止将用户输入当 HTML。管理员可隐藏内容，针对一个游戏限制用户发言。暂停账号后不能继续发言或发布。
- 正式部署前确定评论与社群内容的保存期限、举报处理人、隐私说明与用户删除申请流程；后台需持续处理滥用内容。
- SMTP、邮件送达和账号创建需要对部署实例实际验证；本地环境没有邮件凭据时无法替用户生成线上社长账号。
