# 账号与社群 V2

## 上线顺序

1. 在隔离数据库恢复一份脱敏备份，执行 `pnpm migrate`，核查旧账号、活动、媒体和草稿。迁移把旧 `admin/publisher` 映射为副社长，把旧 `editor/leader` 映射为社群管理员。旧账号缺少的数字账户填入 `9 + 至少五位补零的数据库用户 ID`，空昵称填入 `成员 + ID`；负责人上线前核对并告知本人。
2. 在服务器受限的环境文件中设置 `SMTP_HOST`、`SMTP_PORT`、`SMTP_FROM`、`SMTP_USER`、`SMTP_PASSWORD`，用实际邮箱测试送达。邮件未配置时验证码注册与密码找回关闭并显示错误。
3. 设置 `PRESIDENT_CLAIM_EMAIL` 与 `PRESIDENT_CLAIM_ACCOUNT` 为指定社长的邮箱和数字账户。两者都匹配且邮箱验证码通过时，注册为社长。使用全新密码；聊天中出现过的密码不可继续用。认领成功后清除两个认领环境变量并重启服务，核对账号等级。
4. 在测试环境完成注册、登录、找回密码、申请与审核、发帖、跨社群越权、通知草稿与审核发布，再部署正式环境。此仓库提交不替代对测试服务器或正式服务器的操作。

## 四级权限

| 等级 | 权限 |
| --- | --- |
| 社长 | 全站发布、审核、账号等级及社群归属调整、站点设置 |
| 副社长 | 全站内容发布、审核社群申请、站点设置；不能调整账号等级 |
| 社群管理员 | 所负责游戏内直接发社群活动和通知、管理发言；全站活动、通知、荣誉、动态和影像先提交草稿，等社长或副社长审核 |
| 普通成员 | 浏览、论坛发帖、游戏社群发言、活动与影像与通知下留言回复；可申请管理已有或新游戏社群 |

社群管理员进入 `/admin` 创建全站内容草稿，将「审核状态」改为「待审核」。审核者在后台检查后发布；未经提交的社区投稿无法发布。审核社群申请在 `/community/review`；批准新游戏时自动发布游戏页面并创建论坛入口。用户可通过 `/community/apply` 提交申请。

用户的邮箱与数字账户不能通过普通账号编辑接口修改；密码通过注册邮箱的六位验证码重设。验证码以 HMAC 摘要保存，10 分钟有效，最多错误五次，邮件 60 秒内不得重复发送，并有限流。用户新建账号必须在验证码通过之后；Payload 的公开用户创建接口关闭。普通浏览不要求登录。

## 运营边界

- 新社群是游戏项目档案和论坛、发言、社群活动通知的集合；它不自动生成未经核实的队伍、荣誉或成员资料。
- 社群内容为纯文本，React 转义输出；禁止将用户输入当 HTML。管理员可隐藏内容，针对一个游戏限制用户发言。暂停账号后不能继续发言或发布。
- 正式部署前确定评论与社群内容的保存期限、举报处理人、隐私说明与用户删除申请流程；后台需持续处理滥用内容。
- SMTP、邮件送达和账号创建需要对部署实例实际验证；本地环境没有邮件凭据时无法替用户生成线上社长账号。
