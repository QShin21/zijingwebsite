## 既有微信入口

| 命令 | 作用和前提 |
| --- | --- |
| `pnpm miniapp:check` | 只读核对原生文件、共享生成内容、绑定、AppID、域名校验和源码体积；不等于官方编译。 |
| `node scripts/wechat.mjs islogin --port <已核实端口>` | 在已有官方开发者工具和开发权限的环境核对登录态；本阶段未调用。 |
| `pnpm miniapp:preview` | 先运行静态检查，再调用官方工具生成新的预览信息和二维码；本阶段未调用。 |
| `pnpm miniapp:upload` | 先运行静态检查，再按实际版本及说明上传开发版；本阶段未调用。 |

脚本沿用 `WECHAT_DEVTOOLS_PATH` 和 `WECHAT_DEVTOOLS_PORT` / `--port`。退出成功还必须有晚于本次启动时间的新回执及有限正数包体；预览另需新二维码。最终记录精确源 SHA、实际版本、时间、官方包体与回执。旧 0.4.0 回执不能替代 0.5.0。开发版上传、预览、微信审核和正式发布分别记录。

现有导入包工具从精确 Git 对象导出：

```sh
python3 scripts/package-miniapp.py --source <完整40位SHA> --output <新的ZIP路径> --readme <说明文件> --checklist <核验清单> --evidence <就绪JSON>
```

只导出原生源码和项目配置，不包含 `miniprogram/package.json`；ZIP 内应用版本由 `src/config.js` 提供。辅助证据须同一 `sourceCommit`、`releaseReady:false`。工具校验项目身份、路径、文件摘要和 ZIP 字节，拒绝覆盖旧输出；这些检查仍不能证明官方编译通过。

## 网站发布准备

沿用 [部署文档](DEPLOYMENT.md)、[10月15日发布记录](NEW_BRANCH_RELEASE_20261015.md) 和 [代码包配方](CLUB_CODE_PACKAGE_RECIPE_20261012.md)。最近一次发布文档记录的应用 SHA 为 `c737d9c1ddeb63e42df6b84cc4384669f9518697`；它是历史记录，阶段 E 未访问生产服务器。后续通过既有受控通道核对实际 systemd 工作目录、启动参数、源 SHA 和 Build ID，不按旧目录标记猜测现场。

`scripts/create-club-code-release.mjs` 要求精确提交、已完成构建和真实构建/依赖 metadata；其固定构建条件为 Linux x64 / glibc 2.36 / Node 24.12.x。阶段 E 本地 Node 24.19.0 的合成构建用于回归，不能冒充该打包器要求的构建证据；历史 Windows 构建也不直接满足这个条件。没有放宽打包器或另建部署通道。

此代码包不包含 `scripts/preflight.ts`，不能假定解包后 `pnpm preflight` 可运行。preflight 会加载环境，环境条件满足后才初始化 Payload 并读取数据库聚合；它不是纯静态检查。阶段 E 仅运行隔离合成的 preflight 回归测试，不运行生产 preflight。未来应在匹配的精确源码及既有受控环境执行并单独记录结果。
