# 角色与发布

| 能力                  | 未登录           | 内容编辑 | 发布负责人 | 分部负责人           | 系统管理员 |
| --------------------- | ---------------- | -------- | ---------- | -------------------- | ---------- |
| 浏览已发布内容        | 仅活动与通知 | 是       | 是         | 是                   | 是         |
| 阅读/编辑草稿         | 否               | 所有内容 | 所有内容   | 所属队伍、赛季、荣誉 | 所有       |
| 发布、撤下、恢复版本  | 否               | 否       | 是         | 否                   | 是         |
| 更改站点首页全局      | 否               | 否       | 否         | 否                   | 是         |
| 管理账号、角色、分部  | 否               | 否       | 否         | 否                   | 是         |
| 修改自身密码/姓名     | 否               | 是       | 是         | 是                   | 是         |
| 上传公开媒体          | 否               | 是       | 是         | 是                   | 是         |
| 修改媒体信息/删除文件 | 否               | 否       | 修改       | 否                   | 修改/删除  |
| 阅读审计              | 否               | 否       | 否         | 否                   | 是         |

多个角色取其授权并集；管理员、发布负责人可发布全部栏目，编辑可维护全部栏目。分部作用域仅授予 leader。若需“某个分部的发布负责人”，后续增加精细发布作用域，不应给当前 publisher 角色后假定它受到分部限制。

普通编辑提交 `_status:published` 拒绝；未传 draft 时强制按草稿保存。版本恢复仅限有发布权限的人。`roles`、`teams` 字段不可自改。跨分部对象ID、team关系变更由服务端检查，前端隐藏按钮仅作体验优化。

前台先校验登录边界：访客只访问活动与通知栏目，另开放登录、注册、找回密码与隐私说明；游戏社群及其他栏目需要有效账号。社群 feed、SSE、联系方式和对应 REST/GraphQL 入口同样鉴权。通过此检查后，公开内容投影仍用匿名身份与 `overrideAccess:false`，继续过滤草稿和未核验荣誉。登录为 leader 时 CMS 接口仅能读取授权分部；正常公开站仍可浏览其他已发布队伍。版本、用户和审计无匿名访问。预览不作为公开 URL，分享预览链接需对方有对应后台权限。

受控特权位置：初始化/演示脚本；钩子内审计与重定向；运维备份；测试。不得将 `context.system` 或 `overrideAccess` 从用户请求体传入 Local API。
