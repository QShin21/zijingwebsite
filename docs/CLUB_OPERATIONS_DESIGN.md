## 三个视角的体验评价

产品经理：游客首页跳转活动符合现有边界，但注册、入社、社群管理身份混在一起，缺少本人状态与下一步。修复文案中退役论坛入口，建立“我的参与”和任务队列；空状态使用真实信息。团队和荣誉合并导航保留旧链接。升推和招新应采用引用投影，避免分裂报名。

学生社团组织者：管理员需要处理待加好友/待拉群、申请退回意见及任职交接。骨干招新应收方向、动机经历、投入时间和一种联系方式；队员报名收游戏 ID、位置、经历和训练时间。角色任免、选拔录取与简介公开授权分开。社群离任、停用账号、无名片、群满和暂停均需可继续的说明。不得为验收真实发邮件、通知或微信。

全栈工程师：现有单角色审批会覆盖原权限；canPublish 同时控制内容和私人读取，不可直接扩给骨干。报名源为 events/community-posts，提升复制会破坏去重。问卷保存需要事务内版本比较。迁移快照落后于手写迁移和退役集合，自动生成的 DROP/重复 CREATE 不可执行。备份必须覆盖数据库图片、本地视频和 S3 对象；ready 需验证新表。CI 的 unit 通过不能替代 E2E。

## 信息架构与状态机

登录后建议：首页、游戏社群、社团活动与通知、代表队与荣誉、加入与招新、我的参与。管理队列按待拉群、建群、升推、骨干报名、建队、队员选拔、荣誉核验分组。360/390/768/1440 视口、键盘、原生返回和弹窗关闭均需验收。

- 入群：网站记录意向 → 用户自报发送好友申请 → 管理员人工确认好友通过待拉群 → 管理员人工确认已入群。可撤回意向；撤回不操作微信。不得把历史注册账号批量标为入社。同用户同群一个有效流程，可重新开启撤回流程。首次人工确认进群才在网站显示已确认入社。
- 建群：提交 → 退回修改/拒绝/撤回 → 批准并初始化 → 社群开放。退回给出可执行意见；可修改重提；检查同游戏已存在；初始化与任职必须事务一致，失败不显示成功。新社群不生成虚构队伍、荣誉或成员。
- 升推：本地发布 → 提升待审 → 退回/拒绝/撤回 → 已提升 → 撤下/待重审。稳定引用 sourceCollection/sourceID/approvedVersion；主动升推记录理由与操作者。本地修改不绕过批准版本，源隐藏关闭所有投影；活动资格、时间、地点修改明确提示。
- 招新：批次草稿 → 发布开放 → 截止/暂停 → 归档；申请提交 → 补充/选拔 → 录取/未录取/撤回。一个批次跨全部社群展示；实际角色授予单独处理。
- 建队：申请 → 补充/拒绝/撤回 → 批准 → 招募/活跃/休整/归档。队员申请由本社群管理员审核；账户、队伍、赛季关联，保留历史阵容；公开简介、头像等由本人另行授权。不宣称未经核实的学校官方队伍资格。
- 荣誉：队员投稿 → 待核验 → 退回/拒绝/撤回 → 核验发布 → 更正/撤下。核实成绩时成员/游戏/队伍/赛季关系，私有证明与公开来源分离；投稿者不能设置 verified。每队唯一档案幂等更新，撤下、更正和简介授权变化同步投影；待审、私有、隐藏荣誉不进公开计数。

## 权限与隐私原则

平台等级、账号状态、微信入社、社群任职、代表队成员分别存储。部门执行/宣传使用相同能力判断。任职包含范围、状态和授予信息；撤职或暂停后现有会话、REST、GraphQL、附件的特权失效。

发布本地内容、审核风采、处理进群、读取报名、导出报名分别授权。骨干负责升推审/主动升推，不默认读取个人报名或名片。最高管理层建群审批沿用现状，任免仍仅社长。申请/作答本人及被授权承办者可见；导出持续鉴权并审计。日志不存完整答案、联系方式、密码或令牌。公开投影最少字段，禁止草稿和私人证明泄露。

管理员名片需展示授权，仅有效任职和正常账号可提供。现有历史资料保持保护，不因新表单最少化删除。骨干/队员表单不收密码、身份证、无关住址，不同时强制多种联系资料；学号、院系需确认资格目的。保存与删除期限待确认，无自动清理。

## 分阶段实施与验收清单

P0/P1 本阶段：环境、仓库与 CI 基线；权限底座、部门、独立社群任职；人工入群、本人状态、建群补充/撤回、管理队列与日志；扩展迁移、隔离恢复和测试。

P2：原内容引用、批准版本、升推申请/主动升推/撤下；招新扩展高级问卷与选拔状态；首页和所有有效社群动态投影。

P3：建队申请、赛季成员关系、队员选拔、简介授权、荣誉投稿、私有证明、合并入口及唯一置顶档案。

P4：角色、跨社群、旧会话撤权、请求伪造上下文、防重复、并发、重试、窗口关闭、匿名与附件缓存、全部流程响应式和无障碍；迁移前后记录/媒体核对；备份恢复、应用回滚、HTTPS 与 FreeKill。生产临时筛选内容先核实，不自动删。

P5：沿用小程序 0.3.1 的 15 作答题型及段落说明，同步源 ID、状态、本人回执、新业务展示与权限。复杂编辑/私有证明/审核先由网页承接；合法域名保持校验。开发工具、真实接口、真机、上传、体验版、审核与正式发布各自记录。微信规范正文尚未核实，不能宣称合规验证通过。

关键验收：注册/保存名片不标入社；用户自报明确标记；人工拉群后确认；跨社群拒绝；并发仅一个流程；无名片/离任可继续；骨干批准后原角色保留；两部门同权限；未授任职无本地/隐私能力；重复建群可处理；初始化失败无成功；提升保留源 ID/去重/问卷/名单；批准版本不被本地修改绕过；招新批次同步含新社群；录取不自动授权；简介未授权不公开；荣誉关系伪造被拒；未审/私有/撤下不进档案；档案幂等；退回/撤回/冲突有回执；旧互动路由仍关闭且历史表保留。

交付包含中文流程、角色矩阵、版本、精确 SHA、实际已测/失败/未测、迁移/回滚与限制。计划不算测试证据。部署版本与 GitHub 对应；暂不实施生产，等待独立只读部署核对结果，不猜服务器或读取私钥。
