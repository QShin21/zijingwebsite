# 执行部 / 宣传部骨干招新网页切片 · 2026-10-12

本切片在 `codex/club-operations-recovery` 上实现；申请骨干与普通入社分别处理。加入已有微信群、申请创建社群仍沿用原入口，不要求填写骨干问卷。代表队、新小程序界面及生产部署不在本次范围。

## 网页流程

社长/副社长从账号进入 `/staff/manage`，创建草稿，设置开始/截止时间并编辑现有问卷引擎中的问题，然后发布。首页社团通知和每个游戏社群的通知页动态引用同一当前批次，后来新建的社群也使用同一链接。一个批次只保存一份配置，申请按批次及账号唯一保存，活动和原有报名记录不复制。

`/join/staff` 保留旧 CMS 招新卡片，并列出站内批次；`/join/staff/batches/:id` 展示说明、必要资料用途、申请表和本人回执。默认收集执行/宣传方向、姓名、学校院系年级、动机、经验、可投入时间、一种联系方式，作品 HTTPS 链接选填且不抓取内容。不要求身份证、住址、健康信息或多种联系资料；不宣称学校资格制度或已确认资料保存期限。

批次开放期间本人可以修改、撤回、重提，保持同一申请编号及处理历史。截止时刻即停止提交、修改、撤回；关闭后同样只可查看回执。已录用/未录用锁定本人编辑，管理层明确退回后可在开放期补充。截止并未删除申请，管理层仍可继续人工处理。

管理层按批次、部门意向、申请状态筛选，人工设置选拔处理中、待补充、录用、未录用。退回或未录用必须有本人可见反馈；内部备注仅管理层可见。录用不会写入账号角色；角色任免仍另行操作且仅社长可任免。全部回执和反馈通过网站提供，本切片不发送邮件、微信或真人通知。

## 集成分支审查修复 · 2026-10-12

`codex/club-integration-20261012` 从已通过 CI 的 `ed965ef457b5913d4590753c9d931e82811244b9` 开始，本轮仅收口以下三项边界。

允许管理层将已发布批次保存为草稿。撤下后，详情页通过本人申请的最小标题投影继续打开旧链接，`/join/staff` 单独提供本人回执及分页；普通公开批次、首页和社群当前入口继续隐藏草稿。页面及 API 只使用申请时的标题、题目/答案快照和本人反馈，不读取新草稿的说明、时间或问卷。撤下 API 的 `form` 为 `null`、版本取原回执，避免把已过滤分支题目的历史快照重新解释为完整可填写表单。游客沿用登录门禁，其他账号无本人申请时返回 404；本人提交、修改、撤回仍受服务端批次读取与开放状态限制。

审核在锁定当前申请并核对 `updatedAt` 后，按以下状态迁移处理。管理按钮使用同一判断；直接 API 同样受控。

| 当前状态 | 允许的审核目标 |
| --- | --- |
| 已提交 / 选拔处理中 / 待补充 | 选拔处理中、待补充、已录用、未录用 |
| 已录用 | 已录用（更新同一结果的反馈/备注）、待补充 |
| 未录用 | 未录用（更新同一结果的反馈/备注）、待补充 |
| 已撤回 | 无 |

待补充或未录用必须提供去除首尾空白后非空的本人可见反馈。最终结果不能直接进入选拔或改成另一最终结果；补充资料或更改结果须先明确退回并留下反馈及审计。本人补充仍要求批次开放，且沿用同一申请编号。已有事务、行锁与版本比较保证同版本并发决定只生效一次；录用继续不授予平台角色。

问卷保存和发布均检查所有跳转边：跳转到后续题或结束时，跨越区间不得包含方向、姓名、学校院系年级、动机、经验、时间、联系方式这七个核心必填字段。核心题继续要求直接可见，结合通用问卷只允许前向跳转的规则，保证每条路线经过全部核心资料。扩展题仍可使用显示条件和合法跳转，允许仅跳过扩展题或在核心资料填完后提前结束。

本轮只使用新建的隔离本机合成库，无新增迁移、生产操作或其他模块合并。最终实际检查和未验收边界见 [集成修复证据](evidence/staff-integration-20261012.json)；精确推送 SHA 与 CI 在交付回复核实。

## 权限与一致性

| 操作 | 本人 | 社群管理员 / 骨干 | 社长 / 副社长 |
| --- | --- | --- | --- |
| 查看本人申请与反馈 | 是 | 仅自己的申请 | 是 |
| 读取他人资料、内部备注、筛选及导出 | 否 | 否 | 是 |
| 修改 / 撤回 / 重提本人申请 | 开放期且无最终结果 | 相同本人规则 | 相同本人规则 |
| 配置批次、人工审核 | 否 | 否 | 是 |
| 录用后自动提升角色 | 否 | 否 | 否 |
| 平台任免 | 否 | 否 | 仅社长 |

当前角色在服务端重新读取，旧会话撤权不继续授予资料读取、导出或审核。直接集合禁止用户写入；受控工作流在 serializable 事务内先锁批次、后锁申请，再比较问卷及回执版本。批次发布另有全局事务锁和唯一当前标识；申请唯一键防重复。审计不保存答案、联系方式或内部备注。
