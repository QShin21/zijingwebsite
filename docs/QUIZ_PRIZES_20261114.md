# 竞猜与共享奖池

网页入口为 `/quiz`，小程序入口为首页「竞猜与抽奖」。两个入口使用同一套账号、活动、答卷和奖池；页面支持中英文界面，活动内容按管理员填写的文字显示。社长和副社长可以管理竞猜，所有可用账号可以参与已发布活动。

## 操作流程

1. 创建活动草稿，填写名称和说明。在「设置奖池」添加奖品名称和总数。一个活动拥有一个共享奖池，之后的每一轮都从同一库存抽取。
2. 新建轮次，填写单选题、每题的选项、答对门槛及可选的截止日期和时间。门槛为 1 至本轮题目数；一次可设置 1 至 30 题，每题 2 至 8 个选项。
3. 发布活动后开放轮次。开放后题目和门槛锁定；成员须一次完成全部题目，每个账号每轮提交一次。管理员可以手动截止，也可以使用预设时间自动停止提交。
4. 比赛结果确定后，管理员为每道题选择正确答案并确认公布。公布前接口不返回正确答案或得分；公布后答案锁定，页面显示本人得分和正确选项。
5. 答对题数达到该轮门槛的成员可自助抽奖一次。每件剩余奖品具有相同的被抽中机会，即某类奖品的概率为该类剩余数量除以奖池剩余总数。奖池抽完时资格保留；管理员补充库存后可以继续抽取。

管理员可查看各轮提交人数和最近 2000 条中奖记录。已有中奖记录的奖品保留原名称，总数不能低于已抽出数量；增加数量会补充相应库存。活动结束后可归档，重新开放后可继续使用现有轮次和库存。需要设置未中奖结果时，可以将「谢谢参与」作为一种有数量的奖品加入奖池。

## 安全与数据

- 接口每次刷新账号状态与平台角色，管理操作限定社长、副社长；成员只能读取自己的作答与结果，中奖名单只向管理员提供。
- 浏览器写入要求同源，微信小程序使用现有 JWT。响应使用 `private, no-store`。
- 同一活动的作答、截止、公布答案、库存调整和抽奖通过数据库活动行锁串行化。每轮每账号只有一份作答；重复抽奖请求返回已有结果，不重复扣库存。
- 新增四张独立数据表，迁移 `20261114_001200_quiz_prizes` 不修改旧业务表。账号删除时关联身份置空，库存和历史中奖数量继续保留。
- 不涉及支付、自动通知或线下兑奖交付；兑奖方式可写在活动说明中，由组织者安排。

## 验证与发布

- `node scripts/verify-quiz-database.mjs` 使用临时 PostgreSQL 和合成账号，执行现有全部迁移及竞猜事务、权限、时限和并发检查。
- `node scripts/verify-quiz-database.mjs --browser` 还会启动本地候选服务，在移动宽度浏览器完成作答、公布结果和抽奖。
- 小程序页面检查与原生页面测试使用 `pnpm miniapp:check`、`pnpm exec vitest run tests/miniapp-quiz.test.ts tests/miniapp-i18n.test.ts`。
- 小程序版本：0.5.29。实际仓库、服务器和微信上传状态以本次部署记录为准。
