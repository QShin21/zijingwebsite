## 用户流程

1. 清华邮箱验证注册、昵称/邮箱登录只建立网站账号。“我的账号”分别显示平台身份、社群任职与网站人工进群记录。历史账号不会被迁移为已入社。
2. 进入游戏社群，查看在任管理员已授权的个人微信名片，保存或在微信识别后加好友。网站明确提醒扫码不会自动进群；成员可选择管理员并“记录加入意向”，随后自报“我已发送好友申请”。
3. 有本社群进群处理能力的管理员从“进群管理”核实好友通过，手动保存“等待拉群”；实际在微信拉群后再确认进群。只有最后的人工确认在账号页显示已确认记录。网站不调用微信加好友或拉群能力。
4. 未确认进群前可撤回网站意向，再开启同一回执；同一用户同一社群始终只有一个记录。撤回不删除微信好友或退出群。已经确认的记录不能由本人改回待处理，退出或更正需联系管理员；正式更正/离群状态后续补充。
5. 无管理员名片、名片撤销、账号停用、任职撤销时，新的加入请求被拒绝，并给出继续联系/参与组织的入口。已保存进度不冒充微信状态实时同步；实际群满、暂停和重新分配的运营配置后续补充。
6. 从“申请成为社群管理员”选择现有游戏或申请新游戏，填写姓名、手机号、2 MB 内个人微信名片、运营说明和可选展示授权。姓名与手机号仅供本人及最高管理审核。新名称已有公开社群时引导选择现有游戏，避免重复创建。
7. 社长/副社长在分页审核队列查看全部申请资料，批准、退回或拒绝；退回和拒绝必须给出具体意见。本人可修改退回/撤回申请并重提，待审申请可撤回，保留同一申请 ID。拒绝记录保留，申诉规则尚未确认。
8. 批准、社群初始化及任职授予在同一事务完成。申请者平台身份、其他社群任职保持原状；新授权默认只含本地发布、风采审核和人工进群处理，私人报名读取/导出分别关闭。批准不证明真实微信群已建好或申请者已进群。
9. 已批准的申请者可以更新个人名片、关闭展示。名片投影同时要求正常账号、在任、任职展示同意、申请批准及申请展示同意；撤销后现有登录会话再次请求即不返回名片。浏览器已经保存到本地的图片无法远程收回。

社团级活动的历史承办者规则为：本人提交的活动，加上已授任职的私人读取/导出能力；社群活动按具体社群能力判断。全局发布的 `canPublish` 保持社长/副社长，不加入骨干。历史 `communityAdmin` 只保留既有社团草稿能力；其社群和私人权限来自回填后的具体任职。所有能力受账号停用限制。

社长在后台用户编辑页分别配置平台等级、骨干方向和各社群能力。`exportSignups` 必须同时开启 `viewSignups`。社长/副社长通过现有审批流程可初始化固定的本社群任职；手动扩大能力、撤任和平台等级调整仍沿用社长边界。新审批默认不授私人数据能力；旧客户端新增任职也默认关闭私人读取、导出与名片展示，已有任职保留当前设置。不得通过审批或测试给真实账户自授权限。社长/副社长任免是否进一步统一尚未确认。

## 服务端、并发与兼容

- 权限在网页动作、REST、报名统计/导出和名片投影重新判断；集合权限也适用于 Payload API，当前 GraphQL 路由未开放并保持 404。HTTP 中的 `context` 不成为可信操作标记；私有申请状态和入群状态只能由受控服务写入。
- 建群决定、本人修改、名片更新和人工进群动作使用 PostgreSQL serializable 事务，事务内重读账号/任职，并比较记录版本。并发审核只允许一个决定；冲突返回可刷新核对的 409。唯一键约束防止重复申请/回执，首次入群请求重试返回同一回执。
- 问卷保存现在在同一事务内读取版本和写入，修复读版本后普通 update 的覆盖窗口。原活动类型/ID、15 种作答题型及段落说明、答案快照、本人修改和去重键保持；三种 CSV 编排和现有生成容量保持。
- 内容发布、风采审核、进群处理、报名读取和导出分别授权。没有私人读取权限时界面隐藏统计/答卷，导出按钮按独立能力禁用；直接访问接口仍鉴权。
- 新申请、审核、权限修改、进群状态及导出写入审计，只记录操作者、对象与状态，不复制完整答案、联系方式、二维码、密码或令牌。
- 小程序服务端 DTO 增加平台方向、独立能力与范围，status 增加 `operationsVersion:1`。当前原生客户端仍为既有 0.3.1，新流程未原生实现、未上传、未提交审核、未正式发布、未真机验证。

## 部署与回滚

目前没有生产变更。保存环境仅确认 GitHub 推送能力，未发现环境安全提供的部署通道；历史文档的服务器路径不等于可用凭据。本轮只读健康检查得到 200，不能据此认定当前生产 SHA、APP_ENV、迁移状态、邮件、S3 或异机备份。

部署前依已有安全渠道核实实际运行 SHA、APP_ENV、systemd/容器目标、数据库迁移登记、媒体目录与对象镜像、备份恢复能力；冻结网站写入后完整备份并在独立数据库恢复、执行迁移和候选构建。保留旧源码、构建、环境摘要及两个现有入口配置；校验 Nginx 后仅切换本网站，FreeKill 保持运行。Nginx 示例已修为 16 MB，需核对真实配置与应用总上传 12 MB/Next 表单 14 MB 相容。

该扩展迁移没有删表/删列或数据类型转换，`down` 明确拒绝删除新记录。原枚举与新状态不能安全删回；**生产执行仍需独立复核并按用户不可逆迁移边界单独停报**。本阶段未执行生产迁移。

旧 1.0 构建缺少新状态、普通账号独立任职、名片撤销及独立私人权限。切换旧构建前运行只读 `pnpm club:rollback-check`；出现骨干、普通账号任职、新申请状态、进群记录、减少的旧授权或撤销展示时退出非零。删除任职会保留 `revoked` 记录，旧客户端社群投影也不能复活该授权；门禁检查全部撤任事实，并独立检查遗留 `communityAdmin` 对所属站点活动会恢复的查看/导出能力，即使当前有效任职已全部撤销，也拒绝危险回退。要求使用保留这些能力的已审查回退构建，通过检查仍需核对实际旧构建。回滚保留新增结构和记录，禁止执行删表 `down`。生产数据库恢复会覆盖恢复点后的写入，属于单独受控灾难恢复流程；本阶段未执行生产回滚或灾难恢复。

仅获 `viewSignups` 的成员可以从活动详情或问卷工作台进入“查看报名与统计”。此入口不显示问卷编辑器；导出另验 `exportSignups`，管理模式、PUT 保存和内容发布仍分别验证原编辑/发布权限。社群活动限对应社群；站点活动另需本人为原组织者，有社群关联时按该社群查看/导出授权，无社群关联时要求有效对应能力。报名行的社群、组织者、问题和答案保留历史归属；直接集合读取以原活动当前最新范围和组织者为权威，活动换社群后旧范围不保留他人答案访问。原活动删除后不再给一般管理角色授予历史答卷读取，但本人回执与既有最高管理权限保留。后端私人操作重新读取当前身份，撤销后的旧会话和内部旧身份均不保留私人能力；骨干不默认获得私人答案，版本恢复和审核权限不扩大。

回退门禁认可的私人授权必须为在任且游戏关系非 NULL 的任职，删除游戏造成的 active 孤儿记录不构成授权。门禁除当前活动最新版本外，按旧 1.0 的 organizer 读取面扫描历史答卷；删除活动保留他人答卷时，也必须拦截会重新开放私人读取的回退。核查只读，不更新用户触发撤任，不删除历史答卷来规避门禁。

备份 manifest v2 将 S3 对象镜像与 `MEDIA_DIR/.showcase-videos` 分开存储/校验，同时保留数据库内图片；备份前后发现写入变化即失败。目录缺失可视为空，但权限拒绝等读取错误必须失败，不能默认为空视频备份。60 表恢复、独立视频及读取拒绝用例已验证，见 [备份证据](evidence/club-operations-backup.json)。Compose 可接收既有 `BACKUP_REMOTE`，但没有凭空配置异机挂载，不能宣称异机备份完成。恢复证据路径可显式指定，避免覆盖历史记录。

## 升推网页切片 · 2026-10-12

本社群发布能力的管理员从活动详情“申请社团级展示”或账号“我的社群升推”填写简易理由。执行部/宣传部骨干、社长、副社长在“审核社群升推”处理待审申请，也可对已发布内容填写理由主动升推或降为社群展示。退回/拒绝需具体理由；本人撤回、修改后重提、审核决定、主动操作和源变化均保留记录。网页提交中按钮禁用，后端以记录版本、唯一来源键、事务和行锁防重复及竞态，冲突提示刷新核对。

升推记录引用原 community-posts 活动，不复制 events 或 event-signups，game 与原活动编号均不移动。社团首页卡片使用审核快照，仍链接原详情及同一报名。升推能力不授内容发布、任免、问卷编辑或私人报名权限。

对待审或已升推原内容的保存会使待审申请退回，或使已升推内容进入“改稿待复审”并立即撤下社团展示；需重新申请和审核。批准快照/版本保留，低权限不能通过原始集合接口改写。版本指纹绑定正文、媒体和原问卷，首页另验当前可公开源内容和批准版本；源隐藏/删除关闭展示。高级角色如确认新稿可主动升推，但必须再次记录理由和新批准版本。

仅新增一张 content_promotions 引用/决定表，保留旧内容、答案、角色及历史表。新增加法迁移只在合成隔离开发库执行，生产未操作。旧小程序接口保持，不包含新的原生升推界面。存在升推记录时，旧构建的回退门禁拒绝忽略这些流程；回退保留新增结构。
