当前源码没有上述报名集合统一的一年 TTL、到期清除或保留任务。撤回、拒绝、关闭、归档和隐藏会保留记录；网页或小程序读不到记录也不能证明删除完成。本轮工具提供人工审查材料，尚未实现或启用自动到期删除，不能据此宣布 1 年政策已经全面落实。

集合没有共同、可信的 `submittedAt`。活动及骨干创建时序与入队草稿转提交、撤回后重提不同；申请可能复用原编号，`updatedAt` 也可能来自审核、反馈或名片修改。入队支持 `draft`，建队现有状态从 `pending` 开始，工具不虚构建队草稿。工具提供以下两个 **技术审查点**，不认定业务到期或删除资格：

- `createdReviewAt`：`createdAt` 加一 UTC 自然年，用于发现旧记录。
- `latestChangeReviewAt`：`max(createdAt, updatedAt)` 加一 UTC 自然年，辅助核对近期改稿、审核及重提。近期修改不会把旧记录从审查清单中隐藏。

日期缺失、无效、未来或逆序转入人工核查；入队草稿单列，不把创建日期冒充报名日期。自然年参考点对闰日取下一年的月末；这里的 UTC 和闰日处理仅用于技术排序，未补造用户未确认的报名起算、续期或处理时限制度。

## 离线清单的使用

[工具](../scripts/registration-retention-review.ts) 只读操作者提供的本地 JSON 元数据，不加载 Payload、数据库、环境文件或网络服务。不包含在线抓取器、新后台页面、删除 API 或任何业务写入。

最小输入为 `schemaVersion:1`、`records`。每条记录只接受 `collection`、正整数 `id`、`createdAt`、`updatedAt`、现有 `status`；不接受答案、姓名、账号联系方式、审核私语、媒体、登录凭证。日期使用带时区的 ISO 时间。最多 10,000 条记录、20,000 条引用及 4 MiB 输入，超限需分批，并明确每批覆盖范围。

可选 `references` 仅接收上述真实来源关联的集合/编号/字段；`_teams_v` 是已有物理历史表的元数据标识，不是新 API 或新集合。`referencesComplete:true` 仅表示操作者声明这份快照的引用核对完整，工具不验证数据库完整性；没有已列引用始终不构成整行删除批准。未提供完整引用时报告明确标注不完整。

以下命令只消费仓库中的合成样本，不导入业务数据：

```sh
node_modules/.bin/tsx scripts/registration-retention-review.ts \
  --input tests/fixtures/registration-retention-metadata-synthetic.json \
  --as-of 2026-10-13T00:00:00Z \
  --output /tmp/zijing-retention-synthetic-review-20261013.json
```

输出目的地须为新文件。工具以 `0600` 权限创建报告，拒绝覆盖现有文件和输入；省略 `--output` 时仅输出到终端。没有 `--delete`、`--purge`、`--apply`、数据库参数或执行模式。合成样本的所有编号和日期均为测试构造，不可导入生产。

报告包含输入覆盖范围、候选记录、参考日期、状态、人工核查原因和已提供的引用。`readOnly=true`、`automaticDeletion=false`、`expiryConfirmed=false` 明确界限；不输出 `canDelete` 或删除资格。`reviewItems` 是待审条数，不是已到期或已删除条数。

准备真实元数据应通过已有、获授权的管理渠道，在单独受控目录保存；不要把真实清单、导出、答卷或删除请求上传仓库。工具不会赋予使用者原来没有的查看权限。操作者身份必须由现有账号权限核验，不能凭“叶佳鑫”姓名或微信字符串绑定账号或绕过鉴权。

1. 接收 `yejx2003` 的删除请求，或按运营需要准备待审元数据。仅收集定位和核验本人所需资料，不索取密码或无关答卷。核验使用已有授权流程；涉及他人或组员时分别确认范围。
2. 记录请求、账号核验结果、集合/编号、快照时间、实际提交/重提时间依据及当前版本。先确认 1 年报名资料的范围，分别标记长期成员关系、其他资料、本人希望停止展示的渠道，避免把撤回当作删除。
3. 通过现有授权入口核对申请状态、成员来源、成立来源、历史队伍版本和社群任职引用。清单没有列出的依赖不能视为不存在；未完成核对时只记录阻断和下一步。
4. 写出具体待处理字段、需保留的最小关系/来源事实、私有附件和所有副本。成员关系长期保留不扩展到原答案、联系方式、完整快照、审核自由文本。需要保留来源身份时，应先设计受控的字段清理或最小来源记录，并验证成立资格、回执、审批和现有必填校验；本轮没有实现该方案，也不绕过钩子或放宽外键。
5. 单独准备可复核的实际处理方案与验证/恢复安排。永久删除、批量清除、不可逆字段擦除及清理备份都需要父任务取得另行授权后实施；本轮到这里停止，不提供可执行清除 SQL 或一键删除操作。
6. 后续获准实施后，逐项核对结果并向请求人说明完成、保留及未完成的范围；只有查验实际处理后才记录删除完成。不编造响应时限，也不把审查报告作为已清除证明。

审查记录可使用以下字段，由负责人在现有受控管理环境保存：`requestRef`、`identityVerifiedBy`、`recordRefs`、`snapshotAt`、`submittedAtEvidence`、`policyScope`、`relationshipRefs`、`proposedFieldScope`、`copyLocations`、`blockers`、`separateExecutionApproval`、`verificationResult`。这是人工记录建议，不是已创建的数据库表、工作台或待办状态机；不得公开记录真实答卷和请求人信息。
