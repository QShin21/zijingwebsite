# 紫荆小程序 0.5.0 设计与实施方案

2026-10-15。开发基线 `83882c014e33055ec65fb73e56ea017467d278e7`。用户已将重构分支 `new` 改名为默认分支 `main`；本轮仅在 `main` 整合并正常推送 `origin/main`，不重建远端 `new`，不使用历史旧 main 的 `e366f3c…` 作为开发基线。

## 目标与范围

“紫荆主场，装进口袋的校园电竞俱乐部。”建立适合原生手机操作的清晰首页、活动日程、社群联系和事务处理界面。保留已重构网站的品牌与外观，原生升级主要由空间、字级、信息主次、组件职责及操作位置承担。完整覆盖现有 25 页、5 个 tab 及各业务模式，不能以首页换肤代替完整重构。

本方案落实主助手下发的 A–F 范围。GPT-6 Astra max 负责开发；独立 QA 由主助手创建的指定测试任务执行。开发自测、浏览器合成映射、微信官方编译/模拟器、真机和独立 QA 分开记录。用户已授权最终推送、紫荆服务器部署、微信 0.5.0 上传；阶段 A 只实现样板和自测，不提前执行发布。

## 设计依据与自审

已实际读取官方 frontend-design：<https://github.com/anthropics/skills/blob/main/skills/frontend-design/SKILL.md>，9,390 字节，Git blob `a5333457c414d20d625f307df945842c0952ecc3`，SHA-256 `d91970639e9f5c37682ac7ab60094d35f1c7c1f38d731bd56396563aee10c1d3`。本轮按“设计计划→对照真实任务→实现→截图检查→修正”执行，使用实际业务字段和路由；装饰不承担功能，状态和动作采用用户能理解的中文。

已有代码并非未重构：25 页 WXML/WXSS 均在前轮改过，颜色已有单源。当前问题是页面经常复用相似横线、长标题和通用记录结构，首页模块串行堆叠，原生字级/间距分散。新设计需要区分主场封面、日期日程、社群联系、档案阅读、填写与审核任务的职责；避免把所有内容换成同一种圆角卡。

初始方向自审：不用旧金属舞台图填满首屏，不新增霓虹/玻璃/装饰英文、emoji 或假统计；不复制网站桌面双栏；不以深色大封面遮蔽浅色默认；不为原生专属布局改动网站 tokens 输出和网页样式。纯场地线条只能作为低对比背景，不能造成额外阅读焦点或冒充校徽。

## 颜色、文字与空间

最新指令明确沿用现有共享暖浅品牌；此前“冷白”措辞不再用于改动色板。四至六核心角色如下，均来自 `src/design/tokens.json`：

| 角色 | 浅色 | 深色 |
| --- | --- | --- |
| 页面底色 | `#f7f5f0` | `#151519` |
| 操作/媒体表面 | `#fffdf9` | `#202026` |
| 主要文字 | `#202124` | `#f6f2f5` |
| 辅助文字 | `#62626a` | `#b6afb9` |
| 紫荆主动作 | `#6f2d67` | `#d2a4cd` |
| 次层强调底色 | `#f1e7ef` | `#322630` |

成功、警告、错误等沿用已有语义色。赛事时间和报名状态的强调必须有文字；不靠颜色独自表达状态。生成的 `lib/design-tokens.js` 不手改；网站 `tokens.css` 和网页外观应逐字节保持。

使用系统中文无衬线。原生样板基准：正文/字段/动作 15–16px，辅助正文 14px，必要元信息至少12px；页面标题26–30px、首页主句30–34px、分区18–20px、条目16–18px，按页面职责选择而非每页重复超大标题。字号允许以 rpx 表达，但320px下不能因等比缩小低于基准。正文行高1.65–1.8，标题1.2–1.4；长标题自然换行，关键反馈不省略。

空间使用4px基数：页面侧距约16–20px，主要分区24–32px，字段16–24px，相关元信息8–12px。组件通过留白/结构区分主次；细线仅用于真实栏目、记录和操作范围。按钮/整行操作/checkbox标签命中区域至少44×44px，独立动作之间留足间隔。小圆角用于字段、媒体和独立操作表面；普通正文与列表不逐项叠加同款卡片。

保留原生系统导航/胶囊、五 tab 和返回栈；不新增自定义导航替代。内容底部计入安全区；固定/底部动作不能遮挡正文、键盘和微信宿主控件。浅深切换不重建页面、不清空表单、不停止在途写入，保留 `zijing_theme` 显式选择及默认浅色。

## 原生基础呈现合同

| 元素 | 呈现要求 | 必须保留 |
| --- | --- | --- |
| 主/次/文字/危险按钮 | 一屏明确主要动作，次动作降权；忙碌与不可用可辨识，正文不靠按钮描边堆叠 | 原事件、data-*、disabled/busy 和确认锁 |
| 字段/选项/错误 | 标签、必填、说明、控件、错误就近；正文和输入均可读；失败保值 | 原校验、16题型、分支、修订、原生输入行为 |
| 状态标签 | 当前状态与下一步组合，使用真实来源 | 服务端 actions，不推断额外权限或伪装成功 |
| 媒体 | 真实封面/图注/授权材料，有图与无图都成立 | 受控URL、证据版本、隐私授权、失败和清理 |
| 日期 | 用实际日期/开始结束/截止区分活动，与名称建立清楚对应 | 原时区/筛选/分页，不编造日程 |
| 页面反馈 | 加载骨架、空态、失败重试、无权、成功回执分别表达 | 不把失败渲染为空列表，不隐藏已有回执 |
| 底部/分段动作 | 在当前任务结尾给出下一步，避免远离字段 | 安全区、键盘、不覆盖系统tab、明确主动提交 |

优先使用现有 WXML 模板与原生元素；若抽取共用视觉层，使用原生专属样式/模板，不能为样板重写业务引擎或改变组件事件传播。隐私 Component 的独立授权生命周期保持。

## A 阶段三个真实样板

### 首页 home：主场与下一步

把“找到同好/进入社群”和“当前值得关注的活动”作为首屏主次关系。品牌行简洁；主句不再与每段大标题竞争。已有活动中选取真实首项作为重点，余项压缩为日程入口；优先通知应可发现；骨干与社群招新传播保留。CMS配置开关、排序、指定推荐、无数据与局部加载失败均保留，不能通过隐藏业务模块换取短首页。

```text
品牌 / 简短身份提示
主场主句 + 进入游戏社群
精选活动：日期 → 名称 → 报名/详情状态
优先通知（真实日期、标题）
参与入口 / 其余按CMS顺序的内容模块
```

访客、已登录、无活动、无通知、长标题及局部推荐失败都应有明确内容，不填入虚构校园照片、数据或荣誉。

### 活动目录 events：日期与参与决策

活动/通知切换和搜索筛选保持原逻辑；活动日期与标题构成主阅读线，地点、类型和报名状态作为次层。结果列表、加载更多、空搜索、网络失败与局部推荐错误分别保留。通知模式使用适合阅读索引的密度，不伪装为赛事卡。

```text
活动 / 通知
搜索与类型选择
日期   活动名
       地点 · 真实报名状态
下一活动……
加载更多 / 明确空态或重试
```

### 社群详情 community：联系与人工进群

社群名/一句介绍后给出“联系管理员”的明确入口；当前进群状态与下一步分开于管理员名片。授权名片、无授权名片、名片加载失败、已报告好友申请、等待实际邀请等状态不能合并。保留简介展开、近况/风采分区、荣誉摘要、招新及当前任职管理入口。明确到微信完成好友/邀请操作，点击/扫码不写成已经进群。

```text
社群身份 + 简介 / 联系入口
我的进群状态 → 下一步
获授权名片 或 无名片说明
真实三步：联系 → 核实好友 → 管理员邀请
近况 / 风采 / 荣誉 / 招新与组织入口
```

## 功能与权限不退化

- 保留真实 API、对象ID/归属、发布/审核范围、角色和社群/队伍任职分离。匿名可读范围按当前源码；原生缺少聚合本人活动报名API和取消报名API，不伪造入口/计数/结果。未审核资料只出现在授权视图，聊天/论坛/评论/互动保持关闭。
- 管理员申请必须主动勾选“我同意展示我的微信名片作为进群联系方式”；沿用实际合同的完整同意文本、默认false和服务器raw true校验，未勾选阻止提交并解释。名片同意不等同平台图片隐私授权。
- 16题型、分支清理、跳转/分页/提前结束、五至六人组、草稿、核对、完整回执、同编号改稿和截止规则保留。高级问卷不降为四种简单题型；原生编辑POST action=edit保持。
- 原form version/record revision/CAS保持；未知写入结果不自动重发，成功POST后GET失败保留已确认回执；手动核对不覆盖未保存输入或推进旧修订。
- 原pending/modal/busy、ticket、账号/路由scope、hide/show/unload和迟到回调守卫保持；一次主动操作最多一条写入。
- 成员简介仍为整份visible，membershipVersion换期锁定旧会话，重载默认隐藏；不伪造逐字段私密能力。
- 荣誉JSON保存、独立MP4上传和正式提交分离；上传100%不冒充业务成功。批准后材料公开的真实后果、受控媒体版本与原审核动作保持；不读取或回退raw videoURL。
- 隐私正文/平台指引/官方同意按钮、拒绝/取消和临时媒体清理保持。业务失败保留字段和说明；审核结果必须来自服务返回。
- 既有原生流程不得降级为复制链接。原本仅网站支持的高级编辑入口可以保留并如实说明，不能当作新原生能力。
