# 代表队核心接口合同 · 2026-10-12

基线 `beac037eafe88b9b82e171e15cfddcca351b838b`；分支 `codex/team-core-20261012`。本文供队员简介、荣誉模块并行接入。建队/成员关系由本模块唯一维护，不新增第二份权限名单。

## 集合与 ID

- 复用 `teams`、`games`、`users`；所有数据库 ID 为 PostgreSQL/Payload `number`（正整数），关系展开时可为 `{ id: number }`，HTTP 十进制字符串须先验证转换；拒绝布尔、数组、浮点和超出 PostgreSQL integer 的值。
- `team-establishment-applications`：社群管理员申请建队；状态 `pending | returned | rejected | withdrawn | approved`；批准后关联唯一 `team`。
- `team-recruitments`：`team` 的招新批次；状态 `draft | open | closed | archived`；含开始/截止时间、可配置 `signupForm`。开放要求建队已获批准，截止按服务器 UTC 判断。
- `team-join-applications`：每 `recruitment + applicant` 一条申请；状态 `draft | pending | returned | rejected | withdrawn | approved`；私有答案及表单版本快照。
- **`team-memberships` 是唯一权威成员关系**：每 `team + member` 一条，`status: active | revoked`；`id` 即 member/membership ID（number），`team`、`member`、`game` 均为 number 关系；`member` 关联 `users`；可选 `season` 只能属于该队；`game` 是服务从 team 派生的受保护作用域投影，调用者不能传入。记录 `joinedAt / leftAt / revokedAt / sourceApplication`。撤销和离队均变为 `revoked`，重新批准复用该 ID；重复并发批准收敛到同一关系。
- `teams.teamStatus: unestablished | active | resting | archived`；旧内容默认 `unestablished`，不自动把历史阵容文本或 `users.teams` 导入成员表。`teams.establishmentApplication` 指向批准的建队申请。`seasons.members` 仅历史获准公开文本，不授权限。

## 只读服务（`src/lib/team-memberships.ts`）

```ts
type TeamMembershipView = {
  id: number; teamID: number; userID: number; gameID: number;
  seasonID: number | null; status: 'active' | 'revoked';
  joinedAt: string; revokedAt: string | null; leftAt: string | null;
};
getTeamMembership(payload, { teamID: number, userID: number, req?: PayloadRequest })
  : Promise<TeamMembershipView | null>;
getActiveTeamMembership(payload, { teamID: number, userID: number, req?: PayloadRequest })
  : Promise<TeamMembershipView | null>;
listActiveTeamMemberships(payload, { teamID: number, req?: PayloadRequest })
  : Promise<TeamMembershipView[]>;
getTeamMembershipByID(payload, { membershipID: number, req?: PayloadRequest })
  : Promise<TeamMembershipView | null>;
requireActiveTeamMember(payload, actor: Pick<User, 'id'> | null, teamID: number, req?: PayloadRequest)
  : Promise<TeamMembershipView>;
requireTeamManager(payload, actor: Pick<User, 'id'> | null, teamID: number, req?: PayloadRequest)
  : Promise<void>;
canManageTeam(payload, actor: Pick<User, 'id'> | null, teamID: number, req?: PayloadRequest)
  : Promise<boolean>;
```

`getTeamMembership` 仅返回最小关系记录，适合历史关联验证；它不会把 `revoked` 视为有效。需要投稿/修改权限时**必须使用 `getActiveTeamMembership`**：每次查数据库当前关系、用户状态和队伍状态，不缓存令牌、`users.teams` 或公开简介。`listActiveTeamMemberships` 同样过滤停用账号与未成立/归档队伍。可传本模块事务 `req`，在同一事务内检查；服务只供服务器使用，不能直接把名单或账号 IDs 暴露给匿名接口。

`canManageTeam` 每次重读当前 actor，当前高权限 `president | vicePresident` 可处理；其他身份须有该队伍 `game` 的有效 `communityOffices.status === active` 且 `handleJoins === true`。平台 `backbone`、旧 `communityAdmin` 标签、旧 `communities/teams` 都不单独授范围。建队申请需该 game 有效 `publishContent` 或 `handleJoins` 任职；建队最终审核沿用 `canPublish`，角色任命仍沿用现有社长能力。

`requireActiveTeamMember / requireTeamManager` 未登录抛 Payload `APIError(401)`，无当前有效资格/范围抛 `APIError(403)`。`get*` 找不到、已撤销、账号停用、队伍未成立/归档时返回 null（原始 `getTeamMembership*` 仍保留撤销记录）；`canManageTeam` 返回 boolean。非法 HTTP ID 用 `teamID` 转换并抛 404。修订/窗口/状态冲突为 409，表单校验为 400；HTTP 不接收 `context`、`overrideAccess` 或客户端传来的 member/game/status 事实。

队员录取仅写 `team-memberships`，不改 `users.roles/communityOffices/communities/teams`。简介模块的公开授权独立保存；荣誉模块验证投稿者当前成员关系及历史成绩关联；均不创建自己的授权名单。

## 独立复核修正 · 2026-10-12

- `GET /api/team-core?mode=recruitment&id=<批次ID>` 保留原字段，新增 `readOnly:boolean`。正常可读批次为 false；批次改 draft 或队伍归档导致当前 ACL 不可读时，仅该批次已有本人申请者返回 `readOnly:true`、`state:"历史申请只读"`。
- 只读回退的 title/teamID、form.questions/intro/start/end 与 version 均来自本人申请的历史记录/`formSnapshot/formVersion`。回退 form 强制 `enabled:false, closed:true`，application 保留原回执与答案；不会读取或暴露隐藏批次当前标题、题目、说明、创建人及内部审核元数据。无本人申请仍为 404；匿名/停用账号仍为 401。旧客户端按非开放 state 与禁用 form 仍可安全处理；新客户端可使用 readOnly 隐藏填写入口。
- `POST save-join` 在只读回退下拒绝草稿保存/修改/重提（409），不创建新资格；既有本人撤回服务仍按原状态/修订/身份校验，回退详情不提供新增写入口。普通入社和其它报名权限保持独立。
- 服务端成员查询函数签名与 `active/revoked` 字段完全兼容。归档判断同时认可 `teams.archived === true` 或 `teamStatus === archived`；任何恢复 active/resting 均要求当前高权限。既有 CMS/REST archived 写口同步两种状态，历史不一致记录也受到恢复保护。低权限并发/旧 revision 无法清除归档；高权限可明确恢复。
- `/teams/manage` 的队伍列表使用 page，建队审核使用 reviewPage；两套分页互相保留并保留 game 筛选。

本修正无需新表/字段或迁移。初次17项核心数据库测试已实际通过；修正后的HTTP/网页与最终CI须在交付回复核验，不能以本段声明为通过证据。
