# 代表队成立与招新 · 2026-10-12

独立分支 `codex/team-core-20261012`，基线 `beac037eafe88b9b82e171e15cfddcca351b838b`。本模块只维护队伍生命周期、招新、申请与唯一权威成员关系；队员简介、荣誉及小程序交由并行模块。实际接口见 [合同](contracts/TEAM_CORE_20261012.md)。

## 网页流程

- `/teams`、`/join/teams` 和 `/account`：进入代表队招新、本人记录与工作台。普通入社在游戏社群处理，骨干招新走独立入口，三种参与流程分别显示。
- `/teams/apply`：本社群有 publishContent 或 handleJoins 有效任职的管理员申请建队，填写队名与组织训练计划；本人可撤回，退回/撤回后修改重提。同社群同名申请去重。
- `/teams/manage`：按当前社群筛选队伍；社长/副社长审核建队，退回与未通过需具体意见。批准在一个事务中建立原 `teams` 内容并回写申请，不改申请人的任何平台或社群角色。
- `/teams/manage/[id]`：本队管理员管理运营状态、招新批次与可配置问卷，逐份人工审核入队，查看和撤销成员关系。休整/归档自动关闭开放批次；归档恢复需高权限管理。未批准或已归档队伍无法开启招新。
- `/teams/recruitment` 与 `/teams/recruitment/[id]`：当前招新窗口、本人申请与成员记录；支持服务端草稿、不完整草稿保存、核对提交、待审改稿、退回/撤回后重提、自查回执和本人离队。截止/关闭后不能改稿或重提，未完成审核的申请仍可撤回。截止/关闭后管理员可审核已经提交的申请，批次归档则停止录取。

创建/编辑问卷复用 SignupBuilder、Questionnaire、既有高级题型和分支模型。核心资料固定为游戏 ID、位置/方向、经历/水平、训练时间和一种联系方式；不要求身份证、住址、健康、密码。核心题不能隐藏或被前序跳转/提前结束跳过，核心之外的合法分支仍可用。公开简介授权独立，不由报名或录取代替。

批次必须有明确未来截止时间才能开放，按服务器时间到点关闭。每队同时一个 open 批次；关闭后可重新配置开放，归档批次不能重开。草稿不进入本社群管理员审核队列。每份提交保存完整表单快照和版本，表单升级不覆盖旧答案；新版本改稿需重新核对核心/扩展题，管理员审核原提交版本。

## 权限与一致性

| 操作                                    | 普通用户/队员    | 当前本社群 handleJoins 管理员 | 社长/副社长      | 骨干无任职/其他社群 |
| --------------------------------------- | ---------------- | ----------------------------- | ---------------- | ------------------- |
| 本人申请/草稿/撤回/离队                 | 本人             | 本人                          | 本人             | 本人                |
| 申请建队                                | 需本社群有效任职 | 可以                          | 可以             | 无本社群任职则拒绝  |
| 最终批准建队                            | 拒绝             | 拒绝                          | 可以             | 拒绝                |
| 招新管理/读取提交资料/审核录取/撤销成员 | 拒绝             | 仅本社群                      | 可以             | 拒绝                |
| 授予平台或社群任职                      | 录取不授予       | 录取不授予                    | 沿用现有任免边界 | 录取不授予          |

每次读取私人申请或执行服务都重新读取当前账号与任职。撤销任职、停用账号、撤销/离队成员、归档或隐藏队伍后，旧会话与旧 Identity 对象不能继续授权限。`users.teams`、`users.communities` 和旧角色标签不能替代当前独立任职；`seasons.members` 仅保留历史公开文字，不生成资格。

`team-memberships` 每队每账号只有一条关系，以 `member` 关联 `users`；数据库唯一索引和 serializable 事务共同保护。重复申请/批准与唯一字段冲突重新读取当前结果；已批准申请重复批准不会复活已撤销成员。重新入队需新的批次申请并复用原 membership ID。关系、旧申请、表单快照、审核日志留存；审计只有操作者、对象、动作和状态，没有原始答案或联系方式。

`POST /api/team-core` 仅接受明确操作及选定输入，服务器自己构建上下文。原集合 REST 写入默认拒绝，不能通过请求体 context/system/overrideAccess 自批或造员；GET 招新仅给当前表单和本人回执，GET 申请列表需当前队伍管理范围。响应为 private/no-store，跨站写入拒绝。归档同步原 teams.archived 字段，公开档案显示历史状态，恢复仍需高权限。没有原始私人资料导出，也没有发送通知能力。
