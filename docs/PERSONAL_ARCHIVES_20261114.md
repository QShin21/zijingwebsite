# 个人记录归档（网站与小程序）· 2026-11-14

## 用途

“我的”页的**申请进度**和**我的赛程**中，每一项都可以归档。归档后，该项从总览隐藏，仍可在“全部申请”或“全部报名”中查看，并在那里撤销归档。

归档只是本人的展示偏好：不会撤回申请、取消报名、删除答案，也不会改变审核状态，对其他用户没有影响。偏好存在服务器上，网站和小程序看到的结果一致。

待办不受归档影响，退回待补充和入队草稿照常显示。公共日程和日程页的“已报名”筛选也照常显示活动。

## 数据与接口

- 新表 `personal_archives (user_id, target, archived_at)`，主键为 `(user_id, target)`，删除用户时级联删除。迁移为 `20261113_000800_personal_archives`，只新增这一张表；回滚只删除这张表。`/health/ready` 会检查表结构和迁移记录。
- `target` 沿用客户端已有的键，并由数据库 CHECK 约束限定：
  - 申请：`staff:ID`、`teamJoin:ID`、`teamEstablishment:ID`、`communityOfficer:ID`（同 `ApplicationItem.key`）；
  - 赛程：`club:ID`、`community:ID`（同 `EventCard.key`）。报名回执中的 `archiveTarget` 由本人回执的活动类型和 ID 生成，活动撤下后仍能恢复。
- `POST /api/v2/me/archive`，请求体固定为 `{ "target": string, "archived": boolean }`，返回 `{ target, archived }`。
  - 设置的是明确的目标状态（不做切换）：归档用 `INSERT … ON CONFLICT DO NOTHING`，恢复只删除本人的那一行。重复点击和并发请求最终只留下同一行。
  - 归档前核对归属：申请必须是本人的且账号为清华身份；活动必须有本人的报名记录（`overrideAccess:false`，并逐条复核 owner）。别人的申请、本人没报名的活动和不存在的 ID 都返回 404。
  - 鉴权与现有 V2 写接口一致：匿名请求返回 401；停用账号返回 403；使用 Cookie 时必须同源（Origin 或 `Sec-Fetch-Site`）；携带 JWT 时忽略 Cookie。多余字段、非布尔值和非法目标返回 400。
- 读取：
  - `GET me`：`applications` 和 `upcoming` 在数据库查询或排序过滤阶段就排除已归档项，之后才截取 8/5 条。`counts` 新增 `archivedApplications` 与 `archivedUpcoming`；`counts.applications` 仍为全部申请数。
  - `GET me/applications`：返回全部记录，每项带 `archived`，分页和总数包含已归档项。
  - `GET me/signups`：每条回执带 `archiveTarget` 和 `archived`。

## 网站

- 我的赛程卡片右侧，详情箭头在上、归档按钮在下，两者垂直排列。按钮位于整卡链接之上，点击不会打开详情。悬停或聚焦时的填充色与 4px 位移同箭头一致；开启减少动态效果后不移动。窄屏下箭头隐藏，归档按钮移到正文下方。
- 申请卡片底部提供“归档”按钮。“全部申请”和“全部报名”中的已归档项显示“已归档”，并提供“撤销归档”。
- 请求进行期间按钮禁用，并以 ref 防止重复提交。成功后刷新服务端页面；失败时在按钮旁显示错误，状态保持不变。
- `MatchCard` 只有在传入 `archive` 时才显示归档按钮，公共日程不受影响。

## 小程序

- 我的页：赛程与申请卡片中的“归档”按钮使用 `catchtap`，不会触发卡片导航。“我的赛程”的更多入口改为“全部报名”，并保留“浏览全部日程”按钮；“申请进度”新增“全部申请”入口。
- 新页面 `pages/records/index?mode=signups|applications`：分页读取 `me/signups` 和 `me/applications`，可加载更多，显示已归档状态并支持撤销归档或归档。成功后只更新当前行，保留分页位置。网页链接 `/account?view=signups|applications|history` 映射到此页。
- 写入锁与读取票据相互独立（独立审查后修复）：每次写入持有令牌 `{target, 身份}`，锁只由持有令牌的写入释放，换账号后旧写入的 `finally` 不会解除新账号的锁。
  - 记录页：归档进行中加载下一页、下拉刷新或离页时，成功结果仍按 target 更新当前列表中的行，不会把“处理中”锁死；新读入的行若正处于写入中，保持锁定。页面卸载或换账号后丢弃结果。`session.subscribe` 只在账号身份变化时清空列表并重新读取，同账号 `refreshUser` 不清空列表。
  - 反向时序（复审 19:37Z）：读取先发出、写入先完成、读取后返回时，旧快照不能覆盖已确认的写入。记录页为每次确认的写入记录递增序号；读取开始时记下当时的序号，返回时把之后确认的写入结果叠加到快照上。读取若在写入确认之后才开始，则以服务器数据为准；换账号时清空这些记录。
  - 会话边界（最终复验后补充）：写令牌另外记录发起时的 JWT。两页的结果判定都要求同时满足：`this._write === token`、身份一致、`session.token()` 未变。
    - 换身份（含退出）时清空 `_write`；我的页在刷新时发现账号变化或已退出，也会清空 `_write`。
    - 因此 A→退出→A、A→B→A，以及在其他页面重新登录 A（签发新 JWT），旧会话的响应都不会写回，也不会释放新会话的锁。同账号 `refreshUser` 不改变 JWT，不受影响。
  - 我的页：归档成功后立即从总览移除该行并累加已归档计数，再刷新总览；刷新期间或刷新失败都不会丢弃写入，也不会锁死按钮。刷新返回时，写入中的行保持锁定；写入失败时恢复按钮并用 toast 提示；换账号或退出后丢弃结果。
