## 设计与信息结构

- 阅读区域改为浅灰紫底与白色内容面板，保留深紫首屏和页脚；统一圆角、边线、阴影、焦点、留白和按钮。提升小字字号及正文对比度，减少长页面阅读压力。
- 首页保持 CMS 标题、图片、模块顺序和启停能力；内容卡片根据实际条目数量排版，单条用横向图文、双条并列，避免稀疏内容只占三分之一屏宽。
- 活动、代表队、荣誉、动态、通知、影像、三类招新和各详情页共享更新后的卡片、筛选、状态标签、分页、报名侧栏、正文与空状态。关于、联系、隐私的正文增加独立阅读面板。
- 登录、注册和密码找回改为引导与表单双栏；手机上优先展示操作表单。验证码和账号设置明确分为两步，补充数字账户及昵称要求。
- 个人账号改为信息概览与功能卡片，按现有权限展示内容管理和审核入口。管理员申请、审核、帖子与回复统一表单和面板样式。
- 游戏社群列表增加清晰入口和申请区；社群详情提供活动、论坛、交流与发帖锚点导航。空讨论和未登录状态给出下一步操作。
- 用户表单统一提交中反馈并禁用重复点击。修复移动导航的重复社群入口及其激活状态。保留原生 details 无脚本导航；Escape、外部点击关闭在客户端增强就绪后验证。

## 实施边界

沿用现有 Next.js / Payload / PostgreSQL 和业务服务端动作，未添加依赖、数据库迁移、真实社团记录、第三方照片或外部字体。CMS 原生管理工作区继续沿用 Payload。公开字段投影、匿名权限、草稿隔离、演示标记和角色检查继续由现有服务端执行。

本地验证使用单独新建的开发测试数据库及明确标记的演示资料；没有迁移原有开发数据库或连接生产数据库。此次 GitHub 推送不包含服务器部署。
