# 紫荆电竞社网站｜真实内容与上线条件清单

本清单不要求项目负责人编写代码。资料可以逐步提供，不齐全时 Codex 仍应继续开发后台、页面和空状态。

## 一、首发内容

| 资料 | 用途 | 缺少时的处理 |
|---|---|---|
| 确认使用的社团名称、简称、介绍 | 首屏、关于、页脚、分享信息 | 名称按用户提供；其余留待确认，不编造历史 |
| 社团标识和视觉素材的使用范围 | 品牌展示 | 使用文字标识，不擅自使用学校或游戏官方标识 |
| 已获准公开的活动照片、海报 | 首页、活动、相册 | 使用空状态和中性版式，不用虚构真实活动图片 |
| 一批真实活动资料及日期、地点、条件 | 活动列表与详情 | 没有内容就暂不发布记录 |
| 普通社员、骨干及代表队招新信息 | 招新页面和批次 | 展示“暂无公开招新信息”，不制造开放报名状态 |
| 有效报名链接、群号或其他参与渠道 | 招新和活动 CTA | 不显示失效或虚假按钮；二维码有文字替代 |
| 各游戏项目、队伍、赛季与阵容 | 代表队页面 | 按已确认信息录入；未授权成员信息不公开 |
| 荣誉名称、日期、名次及公开来源 | 荣誉档案 | 未核验记录保持草稿，不计入宣传统计 |
| 公共联系方式与合作渠道 | 联系、页脚、招新 | 不默认公开个人手机号或私人账号 |
| 获准公开的社团动态与历史文章 | 新闻和历史归档 | 优先迁移已核实资料，不批量复制未经确认内容 |

## 二、上线前必须明确的管理事项

确定域名与服务器的管理归属、网站对外主办身份、学校名称/标识使用范围、实际部署地区要求，以及谁批准公开发布。

指定至少一名网站总负责人、内容负责人和技术维护负责人；人员可以兼任。明确账号恢复方式、备用管理人、续费责任和换届交接方式。凭据通过安全渠道配置，不放进项目文档。

确认生产数据库、媒体存储、备份目的地和保留策略。只有本地备份时不能声称具备异机恢复能力。首次上线前完成隔离恢复验证。

如果沿用同一服务器上的另一个网站，向 Codex 提供其需要的非敏感运行信息，例如反向代理类型、已占用端口和允许变更范围；不要让新项目覆盖旧站。

## 三、日常与换届维护

每周检查首页重点、报名链接、二维码、活动时间和联系人是否有效。每次活动后补充结果、回顾和相册。新招新、新赛季新建记录，不覆盖历史。

换届时变更后台账号与分部权限，撤销离任人员访问，交接域名、服务器、仓库、存储、备份与续费责任，并进行一次实际登录和恢复流程检查。

## 四、什么不应让负责人手动完成

负责人不需要修改 React 页面、数据库结构、权限代码、Docker 配置或测试脚本。新增日常内容必须通过后台完成；需要新的业务能力时，由 Codex 按新的开发任务实现。
